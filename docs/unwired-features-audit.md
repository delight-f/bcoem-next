# Unwired / broken features audit

Date: 2026-09-19 · Scope: every user-selectable control and promised action on the site, traced **control → stored column → consumer**, across 12 audit slices (A1–D3). Read-only audit; nothing was changed.

Method: each slice enumerated the controls in its views, resolved storage through the save path, and searched `app/` + `resources/views/` for real consumers. Verdicts use the controlled vocabulary (`wired`, `not-consumed`, `not-saved`, `ui-only`, `broken`, `gated`, `needs-decision`). Evidence is always a `file:line`; generated `app/Domain/*Row.php` classes and `app/Session/Prefs.php` are excluded as non-consumers, and `.slop-scan.cache.json` is never cited.

Overall verdict: **the port is largely wired.** The overwhelming majority of controls have a live consumer (Appendix A). The defects cluster in four places: (1) **report/export options chosen by query string that the receiving controller never reads**, producing a silently different document; (2) a handful of **preference columns saved but read by nothing**; (3) several **server-side enforcement gaps** where the UI or a preference promises a refusal the POST path does not make; and (4) **data-loss-on-save** paths where hiding a field writes `NULL` over a stored value.

### Highest-impact items

**High:**
- **B1-01** — `prefsCurrency` (a display token like `'$'`, `'euro'`) is used as the gateway **ISO currency code**; Stripe has no guard (checkout errors), PayPal fails closed.
- **C2-02** — `prefsStripe.currency` is read but **never written**; no screen offers an ISO-currency control, so the fallback can never yield a valid code.
- **C2-01** — Stripe goes live at checkout on `account_id` alone; with no/wrong webhook secret the webhook verify fails and **the entrant is charged while the entries stay unpaid**.
- **B2-01** — the six **Tie Break Rule** selects post codes (`TBFirstPlaces`) but the save validates `integer`, so any non-"Unused" rule **422s the whole Best Brewer tab** and can never be stored.
- **D2-01** — hiding the MHP field (`prefsMHPDisplay=0`) makes it absent from the POST, and the save writes `brewerMHP = NULL` — **hiding a field destroys the stored value**.
- **D1-01** — the Results/BOS-Results matrix: only `go` is read, so "All with Scores", "Winners Only with Scores", "All without Scores" and "HTML" all return the same winners-only PDF.
- **D1-04** — ~18 Data Exports links each promise a distinct dataset; **`go`/`filter` are unread** and only the filename changes — every link streams the full all-entries CSV.
- **C3-04** — the participants **Assignment(s) modal** echoes a Collection → `Collection could not be converted to string` → **HTTP 500 on the whole participants page** (on legacy data that carries the role CSV).

**Notable medium:**
- **A1-03** language fallback codes are malformed (`CS-Cs`), so the runtime toggle silently degrades to English-only when `prefsLanguageOptions` is NULL.
- **A2-01 / A2-02** competition-wide Total/Paid entry limits are a **render gate only** — a direct POST exceeds the cap.
- **B3-01/02/03** three judging-preference columns (`jPrefsRounds`, `jPrefsMinWords`, `jPrefsScoreDispMax`) are saved and read by nothing.
- **B3-04** a built URL missing its `?` → 404 on the tables-list pullsheet icons; **B3-05** a "which judges were un-assigned" caution modal that never fires; **B3-06** `prefsEval=off` leaves every `/eval/*` route reachable; **B3-07** the scoresheet identifier preference is honoured by neither option.
- **C3-03** delete-account icon is a GET to a DELETE route (405); **C3-05** "Assigned As" prints a JSON blob; **C3-08** the purge dashboard renders every card three times; **C3-10** the inline judging-number save does no validation.
- **D1-02 (also C3-07)** `ParticipantSummaryController` reads no query params — every print variant is the same list; **D1-03** Table Cards ignores `location`.
- **D2-02** the contact-form gate is view-only (a crafted POST still emails); **D2-04** required entry fields are enforced on edit but not on add.
- **D3-01** the judge/steward waiver checkbox is client-side only and the server **substitutes `'Y'`**; **D3-02** the security-question reset path has no throttle and enumerates addresses; **D3-06/D3-07** a structured evaluation's ticks never render on read-back and the import confirmation page is orphaned.
- **C1-01/C1-02/C1-03** the Banner Images rotation UI, the mods "Extends Admin Function", and four Competition Info text areas are saved but consumed by nothing.
